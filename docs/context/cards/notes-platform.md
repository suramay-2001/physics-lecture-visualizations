# Card: the 709 lecture notes platform (and the Optics Lab, its second collection)

Design `docs/roles/proposals/W-709-notes.md`; rulings `docs/roles/decisions/qc709-notes.md` (W1 to W12). Routes: one lazy route `#/709/notes/:id?` (index without `:id`, page `N8`; `/709/notes/L8` redirects, `L<k>` is 448's; the param must be named `id`: bridge chips read the page's chapter from it). Topbar "Notes" on 709, a hero link on the 709 home. Code: `content/qc709/notes/` (`kit.ts`, `N<k>.ts`, `N<k>.values.ts`, `index.ts`, `values.ts`, generated `meta.generated.ts`), `content/unitNotes.ts`, `pages/NotesPages.tsx`, `components/UnitNotesLink.tsx`, `styles/notes709.css`.

**Model.** A notes lecture is a typed `NotesSpec` turned into an ordinary `Lecture` at module load by `notesLecture(spec)` (pure, no compiler chunk; throws `NotesSpecError` listing every `notesProblems`):
```ts
export const N8: Lecture = notesLecture({ number: 8, title, date: '2026-10-02', topics: [3 to 8 phrases], length: 'short' | 'full',
  symbols: { '\\psi': 'n8-bell:b1' },   // TeX symbol -> section id or generated beat id (1-based)
  sections: [{ id: 'n8-bell', label: '§C' /* no space */, title, pages: 'pp. 25–26' /* p. N | pp. N–M, first page never decreases */,
    summary: 'ONE plain sentence <= 40 words (no TeX, no tags)', body: [{ text, figure?: { stage, caption }, claims?: [claim(…)] }] }] })
```
Section = `Unit` (id `n8-slug`, title `§C Name`, `visual` = the Papers placeholder), paragraph = `Beat` (`phase: 'lecture'`, `text` only, id `n8-bell:b2`; a `caption` exactly when it has a figure). `N8` belongs to `qc709` by id (`courseOfId`, `isNotesId`, `chapterName` = "Lecture 8 notes") but is NOT in `QC_CHAPTERS` or the outline: lists never see it; `tracksOfChapter` = `['ground']`, `sentenceCapOf` = 40 (one voice, Formal register, symbols defined at first use). Window: short 150 to 300 words of prose outside `$…$`, full 900 to 1,500; a paragraph <= 120 words, 1 to 3 (short) or 2 to 12 (full) per section.

**Numbers (W3, W12).** Every decimal is a claim. A number a 709 CHAPTER owns is cited by the chapter's own key (`q8ThermR`: `import { V } from '../Q8.values'`, `claim = keyedClaim<…>()`, no copy, no second twin; the key must exist in the merged 709 values, `notes.test.ts`). Only a number no chapter owns gets an `n8…` key in `N8.values.ts` plus a numpy twin `pipeline/claims_notes/n8.py` -> `physics/__fixtures__/claims-notes/n8.json` (run twice, `cmp`). Per lecture, not per section: full >= 3 numbers shown, short >= 1 (`claims.test.ts`).

**Links.** Notes -> chapter: ordinary `<<qc-q6-bell-basis|Unit 6.2>>` (a row in `qc709/bridges.ts`; a row never used fails). W4: every section of every lecture links >= 1 built unit (`notes.test.ts`). Feeds are DERIVED from those bridges (`meta.test.ts` -> `NOTES_META[].units[].feeds`, reverse index `NOTES_BY_UNIT`); `qc709/registry.ts` registers the notes meta, the index and the generated bridges `qc-<section id>`, so each chapter unit shows "From the lecture notes" chips with the usual return bar (`UnitNotesLink`, handed to the chapter card by `Chapter709Page` through `UnitAsideContext`, a slot in `UnitView`). `ret=qc709~N8~n8-bell:b2~0.4~formal` is valid once N8 is registered; the page restores the paragraph and its focus (`.notes-beat[data-beat]` in `BEAT_SELECTOR`).

**Figures.** One static state per figure (end of its hold, s = 1): `SvgStill` on screen for the SVG kinds, `FigureFor` for print and for the flat GL kinds (`bloch bloch-ball hilbert-plane operator-space lab-r3`); `hopf` is refused. No stage host, no canvas. Numbered `N8.1, N8.2`; the page's `data-figures` counts them. No new print button (W9).

**Entry budget.** The entry carries only: the id helpers in `courses.ts` (`courseOfId`, `isNotesId`, `chapterName`, the notes registry), the `UnitAsideContext` slot, one lazy route and the topbar link, and `registerLoaders` in `load.ts`. Everything else (loaders glob, chips, reverse index, listing, kit, pages) is lazy: keep it so (the notes platform used ~1.7 KB of the 497,500 B budget).

**Chunks (rule r).** Nothing of `content/qc709/notes/` or `NotesPages.tsx` in the entry; each `N<k>.ts` + its values in one chunk; no chunk holds two notes lectures or another lecture's story, content or glossary module (a chapter's `*.values.ts` is allowed, W12); the listing rides in the 709 registry chunk; the page imports no lecture statically.

**Weekly checklist for a new lecture (W10; no other shared file changes).** (1) `qc709/notes/N<k>.ts` (+ `N<k>.values.ts` only for numbers no chapter owns); (2) its twin `pipeline/claims_notes/n<k>.py` (if any own key); (3) rows for new bridges in `qc709/bridges.ts`; (4) `UPDATE_META=1 npx vitest run src/content/meta.test.ts` TWICE (second run writes nothing); (5) `'#/709/notes/N<k>'` in `e2e/security.spec.ts` `ROUTES`; (6) one `BUILT` entry in `e2e/notes.spec.ts`. Plan `docs/roles/proposals/P-N<k>-story.md` (sections as units); `node pipeline/context/build_context.mjs N<k>`.

**Two collections, one machinery (the Optics Lab).** `collection` of a `NotesSpec` is omitted (notes) or `'optics'`. Notes = ids `N<k>`, sections `n<k>-…`, claim keys `n<k>…`, route `#/709/notes[/N8]`, files `content/qc709/notes/`. Optics = ids `O<k>` (`O1`…`O9`), sections `o<k>-…`, claim keys `o<k>…`, route `#/709/optics[/O3]`, files `content/qc709/optics/` (`O<k>.ts`, `O<k>.values.ts`, `index.ts`, `loaders.ts`, `values.ts`, generated `meta.generated.ts` = `OPTICS_META`, `OPTICS_BY_UNIT`), twin `pipeline/claims_optics/o<k>.py` -> `physics/__fixtures__/claims-optics/o<k>.json`, plan = the single `docs/roles/proposals/P-optics-lab.md` (the generator uses it for every `O<k>`; a `P-O<k>-story.md` wins if one exists). Differences, all in the kit and the page: an optics spec has `book` (required: "Foot, Atomic Physics, ch. 9"; forbidden on notes) and no required class date; the index row shows book chapter + printed pages + "feeds Q…" instead of the date; `chapterName('O3')` = "Optics Lab O3", bridge labels "Optics Lab O3, §2, pp. 12–14". Shared on purpose: `notesLecture`, `notesProblems` (messages start `O3 …`), the one-voice lint profile (`tracksOfChapter`, cap 40), `courseOfId` (both are `qc709`), `parseReturnSyntax` / the return bar (`COURSES.qc709.chapterId` takes `[QF]\d+|[NO][1-9]\d*`, so `ret=qc709~O3~o3-cooling:b2~0.4~formal` is valid), `NotesPages.tsx` (a `VIEWS` table: words, light registry, fact line; the two routes share one lazy chunk), `unitNotes.ts` (a reverse index per collection: `notesForUnit(unit, 'optics')`), `UnitNotesLink` ("From the lecture notes:" then "From the optics lab:", `data-unit-notes` / `data-unit-optics`), the generated bridges `qc-o3-<slug>`. Entry cost: `collectionOfId` + two registries in `courses.ts`, one route, the topbar link "Optics lab" (+688 B raw of the 497,500 B budget; 146 B left, so a further entry edit needs a measurement first). 709 home: one link. `meta.test.ts` writes both generated files (`UPDATE_META=1` TWICE). Checklist for a new optics page (no other shared file changes): (1) `optics/O<k>.ts` (+ `O<k>.values.ts` for numbers no chapter owns), (2) its twin `pipeline/claims_optics/o<k>.py` (run twice, `cmp`), (3) rows for new bridges in `qc709/bridges.ts`, (4) `UPDATE_META=1 npx vitest run src/content/meta.test.ts` TWICE, (5) `'#/709/optics/O<k>'` in `e2e/security.spec.ts` `ROUTES`, (6) one `BUILT` entry in `e2e/optics.spec.ts`; a new bench picture is one preset in `widgets/opticsBench/presets.ts`. Shared test helpers: `notes/checks.ts` (`unlinkedSections`, `foreignClaimKeys`); per-page tests `optics/optics.test.ts`; chunk rule (r) has an optics half (`opticsLeaks`: never beside another page, a notes lecture or a chapter's story, content or glossary module).

**Paragraph widgets.** A paragraph (notes or optics) may carry ONE widget, `NotesPara.widget?: WidgetSpec` -> `Beat.widget`, drawn in place under the paragraph and its figure in `div.notes-widget`; the page waits for the widget chunk before it renders (`widgetKindsOf` + `useWidgetsReady`), so nothing reflows after mount. Not `bloch` (three.js). A widget caption is one plain sentence with no digit. The widget-spec gate (`widgets/visualSpecs.test.tsx`) reads every paragraph widget of both collections; `notesProblems(spec, { widget: opticsWidgetProblems })` (tests) names the unknown preset. **`optics-bench`** (props `{ preset: string }`): a generic sweep bench; `widgets/opticsBench/presets.ts` holds the lazy table preset id -> `{ title, question, sliders: {key,label,min,max,step,default,unit}[], x: {label,unit,from,to}, y: {label,unit,from?,to?}, y2?: {label,unit,from?,to?}, curves: (p) => {label, f, axis?: 'left'|'right'}[] (<= 4), markers?: (p) => {x,label}[], readouts: (p) => {label,value,unit,digits}[] }`. No result is typed in a preset (curves, markers and readouts call the engine; `OpticsBench.test.tsx` lints the source); `y2` and `axis: 'right'` draw a right-hand axis only when a curve reads it. A new preset = one entry in `presets.ts` + one line of content; `opticsPresetsProblems()` and the gate check it. Demo preset: `lorentzian` (`rabiPeak`, `rabiFlipTime`).

**Tests.** `notes/kit.test.ts` (each rule fails on a mutation), `notes/notes.test.ts` (per lecture), `unitNotes.test.ts`, `components/UnitNotesLink.test.tsx`, `pages/NotesPages.test.tsx`, `e2e/notes.spec.ts`; shared lints read notes as ordinary lectures (`content.test.tsx`, `symbols.test.ts`, `claims.test.ts`, `bridges.test.ts`, `verbatim.test.ts`).

**Optics Lab content (built).** Pages `O1`-`O6` (`qc709/optics/O<k>.ts`, `.values.ts`; shared `format.ts` `r` / `n0` / `near`): O1 slowing a sodium beam, O2 molasses, O3 below the Doppler limit, O4 magnetic traps, O5 traps of light, O6 applications; 32 sections, one bench preset per Try-it paragraph (12 presets). Values are the engine's numbers rounded to the printed digits; twin `pipeline/claims_optics/o.py` writes `o1..o6.json`. Corrections: `NotesSection.corrections?: Omit<Correction,'unit'>[]` (plain Unicode text, engine `check`) -> `Lecture.corrections` (`unit` = the section) -> a box in `NotesPages.tsx`. Glossary: `qc709/optics/glossary.ts`, ids `qc-op-*` (24), merged into `qc709/pack.ts`. (2.2)`, no `Table 1.1`; claim = magnitude in the printed unit.
